
# Add Learning-Outcome Features

Goal: make HBK Maths Quest measurably help students *understand* maths better — not just answer more questions. All six features work across grades 1–10 with the existing localStorage-only progress model (no auth required).

---

## 1. "Explain my mistake" button (inside QuizRunner)

When a student gets a question wrong, show an **"Explain why"** button alongside the existing explanation. It calls a new server function `explainMistake({ question, studentAnswer, correctAnswer, grade })` that returns a friendly, age-appropriate breakdown:
- Where the student's thinking likely went wrong
- The correct method, step by step
- A "Try one like this" mini-prompt (one similar practice question)

Why it matters: the current static `explanation` field is short and generic. A targeted explanation tied to *their* wrong answer is the single highest-leverage learning lever.

---

## 2. Mistake Bank + Smart Revision

Auto-save every wrongly answered question into a **Mistake Bank** (localStorage, keyed by grade + chapter). New route `/revise` shows:
- All saved mistakes grouped by chapter
- A **"Revise 10 mistakes"** button → re-runs them as a fresh quiz (shuffled, with re-worded variants generated by a new `regenerateVariants` server fn so it's not pure memorization)
- Auto-removes a question after the student gets its variant right twice in a row (spaced-repetition lite)

Why it matters: students learn most from revisiting *their own* errors. Today, wrong answers vanish the moment they click "Next".

---

## 3. Weak-Topic Radar (on `/progress`)

Track per-chapter accuracy (already partially there) and surface a **"Focus areas"** panel on the Progress page:
- Top 3 weakest chapters across all attempted grades (sorted by accuracy %, min 5 questions attempted)
- One-tap "Practise 10 questions on this" button per topic
- A small radar/bar visualization

Why it matters: students (and parents) currently see stars and XP but no signal on *what to work on next*.

---

## 4. Step-by-Step Solver (new tab in Tutor)

Extend `/tutor` with a second mode: **"Solve my problem"**. Student types or pastes a maths problem; server fn `solveStepByStep` returns numbered steps with reasoning at each step, plus a final answer in a highlighted box. Different from the chat mode in that the output is structured (rendered as a clean step list, not freeform chat).

Why it matters: most homework help asks are "solve this", not "explain this concept". Structured output is much more useful than chat for that.

---

## 5. Concept Cards per chapter

On the chapter page (`/grade/$gradeId/chapter/$chapterId`), add a **"Learn first"** section above the quiz with 3–5 AI-generated concept cards for that chapter:
- Definition / formula / key idea
- Worked example
- Common pitfall

Generated once per chapter, cached in localStorage. Students can read them before attempting the 25 questions or use them as a refresher.

Why it matters: right now students jump straight into the quiz with no recap. A 60-second concept refresher dramatically lifts first-attempt accuracy.

---

## 6. Adaptive difficulty in chapter quizzes

After every 5 questions in a chapter quiz, look at the score:
- ≥4/5 correct → next batch leans harder
- ≤2/5 correct → next batch leans easier + adds a tiny "hint" line before each question
- otherwise → stay mixed

Implementation: extend `generateChapterQuiz` to accept an optional `difficultyBias: "easier" | "harder" | "mixed"`, and have `QuizRunner` re-fetch the remaining questions mid-quiz when the bias flips. Cache by `(chapter, bias)` so repeat plays are still instant.

Why it matters: a fixed 25-question pack frustrates weaker students and bores stronger ones.

---

## Technical sketch

New server functions in `src/lib/quiz.functions.ts`:
- `explainMistake` — single targeted explanation
- `regenerateVariants` — variant questions for revision
- `solveStepByStep` — structured solver
- `generateConceptCards` — chapter concept cards
- `generateChapterQuiz` — extended with optional `difficultyBias` param

New / changed files:
- `src/routes/revise.tsx` (new)
- `src/components/quiz/QuizRunner.tsx` (Explain button, mistake-bank write, adaptive re-fetch hook)
- `src/components/chapter/ConceptCards.tsx` (new)
- `src/routes/grade.$gradeId.chapter.$chapterId.tsx` (mount ConceptCards)
- `src/routes/progress.tsx` (Focus Areas panel)
- `src/routes/tutor.tsx` (Solve tab)
- `src/hooks/useProgress.ts` (mistake bank + per-chapter accuracy helpers)
- `src/components/home/ModeCards.tsx` (add "Revise mistakes" tile)

All data stays in localStorage — no DB migration required. All AI calls reuse the existing Lovable AI Gateway (`google/gemini-2.5-flash-lite`) so no new keys.
